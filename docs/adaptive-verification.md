# V0.3 自适应算法：实现前确定的失败场景

此文件和新增 E2E 用例先于算法实现。验收通过真实 CLI 或 Swift 表单 → 包内 Rust 子进程 → HTTP/JSON，不写函数级单元测试。

| 场景 | 预期行为 |
| --- | --- |
| 旧版默认调用、百分比、手动区间 | 原输出与资金公式保持兼容；CLI 默认 classic |
| adaptive 未提供历史、只提供手填 ATR、使用非 ATR 区间 | 明确失败，不自动切回旧算法 |
| 实际历史不足 120 根、ATR 预热后不足三个验证段 | 明确失败，不补造 K 线 |
| 固定绝对 SL/TP 与滚动选参混用 | 明确失败，避免把当前价位带入过去 |
| 固定格数 | 全部候选、滚动验证和最终方案保持指定格数 |
| 震荡历史 | 比较扣费收益、库存清算、回撤和成本压力；发展段评分不低于可行旧策略 |
| 最后 20% 历史变动 | 选参结果、发展段评分和发展段数据保持不变；只改变最终检验和当前线位 |
| 单边下跌、最终检验亏损、缺少有效成交 | 输出观望及原因，不声称保证盈利 |
| 开盘跳空跌穿 SL | 清仓价使用更差的开盘价；库存损失可超过 SL 情景预算 |
| OHLC 内部成交顺序不明确 | 同时运行 O-H-L-C / O-L-H-C，收益取较差者，回撤取较大者 |
| 手续费与额外成本 | 初始购币、网格买卖、储备币和最终清仓均计成本；另运行双倍成本 |
| 资金、订单金额或精度不可行 | 明确失败，不为回测收益放松现有约束 |
| 导出与显示 | JSON 保存选参、旧版对照、最终检验、时间界限、观望原因；Swift 正确解码 |
| 旧版持久化表单 | 新增算法字段补默认值，既有资金、周期和代理设置保留 |
| macOS 应用 | 实际打包 Rust/Swift、版本一致、签名校验、ZIP 校验、包内真实后端验收 |

## 真实公开行情比较

2026-10-04 实际读取币安公开 BTCUSDT 1000 根日线，覆盖 **2024-01-08 至 2026-10-03（UTC）**；另读取同批截止日期的 ETHUSDT 180 根日线。全部已收盘，没有账户接口或真实订单。

BTC 使用同一行情切片、同一规则快照、同一参考价 85174.01；ETH 快照参考价 2693.12。每项最多投入及账户资产均为 600 USDT，风险 2%，最低单笔 30 USDT；假设每边手续费 0.1% + 额外成本 0.05%，并做双倍成本压力。**这些是验证输入，不是用户账户费率或当前价格承诺。**

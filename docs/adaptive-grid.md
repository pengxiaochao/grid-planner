# V0.3 自适应网格：算法比较、方法与使用

V0.3 把“最多能放多少格”扩展为“哪些区间和格数在历史成本、回撤及资金限制下更有依据”。新算法比较多个可行方案，并允许输出**观望**。它仍生成币安现货等比网格参数，不接入账户，不持续移动订单。

**无法保证收益最大化。** 可实现的是在明确候选集合、历史样本和成交假设下最大化风险调整评分。未来行情、流动性、手续费与成交顺序无法保证；正的每格收益也不等于整体盈利。

## 开源方案比较

资料核对日期：2026-10-04。下表比较机制和适用条件，不把作者回测当成本项目的盈利证据；未复制这些仓库代码，未重跑其全部实验。

| 算法/项目 | 机制与优点 | 本版采用的经验与适用边界 |
| --- | --- | --- |
| 本项目 V0.2 / classic | ATR、百分比或手动区间；选首个可行最大格数；资金、止损情景和精度约束透明 | 目标是格数，缺少成交、整体净收益及库存回撤评价 |
| [Hummingbot Grid Strike 源码](https://github.com/hummingbot/hummingbot/blob/master/controllers/generic/grid_strike.py) | 控制订单间距、金额、活跃订单及停止边界 | 保留成本与订单硬约束；持续执行及杠杆配置不能直接套用现货参数生成器 |
| [Passivbot](https://github.com/enarjord/passivbot) | 网格与追踪进出场、市场筛选、解除套牢 | 关注库存风险；当前 V8 默认策略与 V7 兼容策略不同，不照搬加仓或杠杆参数 |
| [hftbacktest 高频网格教程](https://hftbacktest.readthedocs.io/en/latest/tutorials/High-Frequency%20Grid%20Trading.html) | 库存偏移报价、持仓限额和延迟建模 | 不能只数成交；盘口、队列和延迟能力超出 OHLC 回放范围 |
| [Dynamic Grid Trading 论文](https://arxiv.org/abs/2506.11921) / [作者代码](https://github.com/colachenkc/Dynamic-Grid-Trading) | 越界重置网格，作者报告指定 BTC/ETH 历史中的优势 | 重置需计成本和持续执行；本版每段固定网格、停止后不重启，未实现论文 DGT |
| [Freqtrade Lookahead Analysis](https://www.freqtrade.io/en/stable/lookahead-analysis/) | 检查指标和信号是否偷看未来数据 | 每段指标只读此前历史；修改最终检验尾部不能改变选参，已有真实 CLI E2E 核对 |

本版选择**受约束静态选参 + 三段滚动发展验证 + 独立最终检验**，适合当前“生成后手工填写币安”的方式。动态追踪、库存偏移做市或 DGT 需要有执行与盘口数据的另一套系统验证。

## 使用方式

桌面默认自适应、ATR、联网行情和 180 根日线。旧草稿补算法默认值，保留资金、周期与代理。旧草稿若为百分比/手动模式，选择经典算法或切回联网 ATR；自适应时清空旧绝对 SL/TP，改用 ATR 停止缓冲。

1. 填最多投入、真实账户资产及风险百分比，核对每边费率和成本余量。
2. 使用真实 ATR 历史，至少 120 根；更大 ATR 周期还需要更长预热。
3. 生成后查看候选数、区间倍数、旧策略对照及最终检验收益、回撤和成本压力。
4. 观望时参数仅供诊断，复制填写按钮禁用，完整 JSON 仍可导出。
5. 历史门槛通过也需核对币安实际预览，不代表下一阶段必然盈利。

CLI 默认 classic 保留旧行为；显式开启新版：

```bash
cargo run --locked -- --capital 600 --live --mode atr \
  --algorithm adaptive --history-bars 180 --json --output plan.json
cargo run --locked -- --config examples/adaptive.toml --live
```

对照旧版，或用自己的真实已收盘 CSV 离线复算：

```bash
cargo run --locked -- --capital 600 --live --mode atr \
  --algorithm classic --history-bars 180
cargo run --locked -- --capital 600 --price 84000 --mode atr \
  --algorithm adaptive --candles /path/to/closed-candles.csv --interval 1d
```

84000 是演示输入，非实时价格。CSV 周期、现价和交易规则须由用户核对；表头和连续性规则与 README 相同。程序不自行加载演示行情，不能仅用一个手填 ATR 数值验证收益。

## 候选区间与格数

`--range-atr-mult` 是搜索基准，默认 3。候选为基准的 **0.5 / 0.75 / 1 / 1.5 / 2 倍**，即默认 1.5 / 2.25 / 3 / 4.5 / 6 ATR。止损和停止价缓冲沿用用户 `--stop-atr-mult` / `--take-atr-mult`，不参与搜索。

每个宽度比较 2 到 `--max-grids` 的所有格数，以及旧版“最大可行格数”政策。该政策每段重算实际格数，JSON `selected_grids=null` 表示选的是这项政策；最终 `grid_count` 始终是当前具体格数。默认共 750 个组合，实际可行数往往少得多。

固定 `--grids N` 时，只比较宽度，所有段和最终方案保持 N，不可行不会换格数。交易所订单上限缩小搜索空间。

每段复用原规划器的最低订单金额、数量/价格步长、双边单格净收益门槛、投入上限、账户止损情景预算以及区间外 SL/TP 约束。优化器不能放松这些条件。拒绝绝对 SL/TP，防止把当前价格坐标带入过去。

## 时间划分与未来数据隔离

设历史根数 M：

```text
预热 W = max(60, ATR 周期 + 1)
最终检验 H = max(20, floor(M / 5))
发展段截止 D = M - H
三个发展段宽度约为 (D - W) / 3，最后一段吸收余数
```

要求 M ≥ 120，且三个发展段各至少 10 根。180 根、ATR(14) 的划分：

| 阶段 | 索引（从 0 开始） | 计算依据 |
| --- | --- | --- |
| 首次预热 | 0..59 | 第一段前的 ATR 与参考收盘 |
| 发展验证一 | 60..87 | 指标只用 0..59 |
| 发展验证二 | 88..115 | 指标只用 0..87 |
| 发展验证三 | 116..143 | 指标只用 0..115 |
| 最终检验 | 144..179 | 锁定选参后评估，不重新排名 |

```mermaid
flowchart LR
    A[已收盘 OHLC] --> B[前缀 ATR 与交易约束]
    B --> C[三段发展回放及评分]
    C --> D[锁定区间和格数政策]
    D --> E[最后 20% 独立检验]
    E --> F[当前行情资金与精度复核]
    F --> G[通过历史门槛或观望及审计]
```

后段可以使用此前已经发生的数据。**发展段参与参数搜索，属于选参数据，不能当成独立最终测试。** 最终检验仅用于展示和启动门槛，不用其结果改选另一套参数。若选定政策在当前行情不可行，报错而不重新调参。

## 成本、库存及回放

每段独立从用户预算开始，用训练前缀末收盘价规划。初始买上方卖格所需币和费用储备币，下方买格留 USDT。每格数量固定，利润不放大数量；不使用杠杆、借币或未分配资金。

- 下穿买价扣 `q × buy × (1 + cost)`；上穿卖价收入 `q × sell × (1 - cost)`。
- 初始购币、逐格买卖、储备币和终止清仓均计每边成本，`cost=(fee_pct+slippage_pct)/100`。
- 权益包含现金、未分配本金及库存；库存估值扣预估卖出成本。不能只计已实现利润、忽略套牢币。
- 段末或 SL/TP 触发后清仓，该段停止后不重启；跨段独立评估，不是连续复利曲线。
- 跳空穿越下方买单按限价成交作保守情景；开盘低于 SL，清仓用更差开盘价。
- `completed_cycles` 为逐格卖出完成数，包含初始卖格；终止清仓不算网格成交。

OHLC 不说明 high/low 先后。本版分别运行 **O-H-L-C / O-L-H-C**，再分别运行普通和双倍成本，共四条情景。收益取对应成本下较差路径，回撤取较大值。这**不是所有可能轨迹的最坏下界**，未模拟限价排队、部分成交和实际成交概率。

```text
本金净收益百分比 = 清仓后净利润 / 最多可投入本金 × 100
回撤百分比 = (当时最高权益 - 当前可清算权益) / 当时最高权益 × 100
```

本金收益含未投入现金，便于比较不同投入候选；不是“建议投入收益率”、账户收益率或年化收益。

## 排名与观望

```text
发展评分 = 平均普通成本本金收益
         - 各段最大权益回撤
         - 各段本金收益标准差
         + 最差一段双倍成本本金收益
```

全部按百分比计算，偏好净收益、低回撤、跨段稳定及成本余量。权重、候选与门槛为预先声明的设计参数，未宣称数学最优；不根据最终检验结果调整。并列时保留遍历首项，容忍度 1e-10。

候选包含旧策略；旧策略全段可行时，选中的发展评分不会低于它。**这是有限搜索集合中的性质，不保证最终检验或未来收益更高。** 旧策略不可行时保存真实错误，不伪造为零收益。

任一条件成立即 `wait`：

- 发展评分不正，或三段中盈利段少于两段。
- 最终检验普通或双倍成本净收益不正，或没有网格成交。
- 最终检验收益低于同段可行旧策略。
- 最近 30 根收盘强单边下跌：方向效率 ≥ 0.65 且净方向向下。

方向效率为 `|末收盘-首收盘| / Σ|相邻收盘变化|`，平盘为零，不是预测准确率。`ready` 只表示历史门槛通过。观望保留当前合法诊断参数和审计，桌面禁用复制。

买入持有基准采用候选同额投入、同起止价及双边成本，剩余现金不动；风险敞口、库存和止损不同。上涨时网格可能落后持有，报告保留这一结果。

## 复算和限制

JSON 新增 `algorithm` 与可空 `optimization`，包含候选数量、选定政策、发展段、旧策略错误、最终检验、时间界限、趋势效率及判定。联网报告保存同批 OHLC 和公开来源；CSV 用于计算，但不伪装成公开 API 快照。

算法在 [optimizer.rs](../src/optimizer.rs)、回放在 [backtest.rs](../src/backtest.rs)，资金约束在 [planner.rs](../src/planner.rs)。失败场景和 E2E 先于实现，见 [本版验收记录](adaptive-verification.md)。

真实限制：历史回放沿用本次规则快照，而非历史当时的过滤器；费率由用户假设，未查账户费率；建仓按前缀收盘价加比例成本，无法保证该价成交；未模拟盘口、限价队列、部分成交、清仓流动性，也没有实时机器人或纸面交易闭环。

不要依据一次有利历史提高风险预算。更长样本不自动更好，长期静态箱体可能早早停止；小时线和日线的结果不能直接比较。真实行情比较及本地应用构建结果见 [adaptive-verification.md](adaptive-verification.md)。

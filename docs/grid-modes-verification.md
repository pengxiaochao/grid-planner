# V0.4 等差/等比与格数解释：实现前验收场景

先确定失败方式并写真实 CLI、Swift 表单到包内后端的 E2E，再修改生产算法；不新增函数级单元测试。

| 场景 | 预期行为 |
| --- | --- |
| 未选择网格类型、旧 TOML / 桌面草稿 | 沿用等比，既有参数与结果保持兼容 |
| 等差模式 | 生成 N+1 个等价差价位；仍按交易 tickSize 取整并保留端点 |
| 等差逐格收益不同 | 独立复算全部相邻买卖价的双边成本，使用最差一格检查门槛 |
| 资金、单笔金额、风险、数量精度 | 两种类型均继续满足现有资金/风险不变量 |
| 粗 tickSize 导致价位重叠 | 明确拒绝，不输出重复挂单价 |
| 固定格数超过成本门槛 | 明确拒绝，不自动减少格数或放宽成本 |
| 自适应等差与固定 6 格 | 三段发展验证和最终检验均使用同一网格类型、尊重固定值 |
| 修改最后 20% 历史 | 不改变等差选参或发展段评分，只改变最终检验与当前参数 |
| TOML 等差、CLI 覆盖等比 | 覆盖顺序正确，输出文件与 stdout 完全一致 |
| 非法网格类型 | 请求前拒绝，不静默沿用等比 |
| 格数与投入关系 | 报告解释历史评分/固定值/最多可行值，不显示不存在的 5 格上限 |
| 桌面选择、显示、复制与导出 | 等差类型一致，旧草稿补等比；观望仍禁用可执行参数复制 |

## V0.3 现象核对

使用上版保存的 180 根 BTC 已收盘日线、参考价 85300、风险比例 100%，投入 600 / 6600 / 66000 USDT 均选 1.5 ATR / 5 格。程序实际搜索 750 个组合，并没有 5 格上限；资金增大主要放大每格数量，评分用百分比，因此最佳格数可以不变。这里的 100% 仅用于复核截图，不是推荐风险配置。

固定截图区间 81993.21～88606.77，默认每边成本 0.15% 和单格净收益门槛 0.3%，经典等比模式在上述三个资金量下都生成 12 格。未取整的理论单格净收益：5 格约 1.2612%，10 格约 0.4776%，12 格约 0.3476%，13 格约 0.2976%，20 格约 0.0880%。资金再多也不会扩大同一区间每格的比例价差。

当前格数不代表最大未来收益。更多格数可能增加触发频率，但降低每格数量/价差，成本、库存浮亏和完整成交次数共同决定总收益。等差与等比定义依据：[币安现货网格说明](https://www.binance.com/en-NZ/support/faq/detail/d5f441e8ab544a5b98241e00efb3a4ab)、[币安收益公式](https://www.binance.com/en/support/faq/detail/688ff6ff08734848915de76a07b953dd)。公式按本程序相邻买卖价独立计算，不照抄网页中的排版错误。

- 实现后 CLI **37 项全部通过**，含既有 29 项与新增 8 项。
- 原生包内后端桌面桥接 **15 项全部通过**，含等差表单、固定 6 格自适应、复制/导出一致及旧草稿补等比。
- 等差示例区间 400～450、5 格生成 400 / 410 / 420 / 430 / 440 / 450；每边费率 0.1%、无额外成本时最差一格净收益按 440 买入、450 卖出独立复算为约 2.0705%。
- 截图区间的等比与等差在 600 / 66000 本金下均允许经典 12 格；固定等差 13 格被净收益门槛拒绝，粗价格步长的重叠价位被拒绝。
- 自适应等差固定 6 格在三段发展验证、最终检验和当前方案保持一致；修改最终 20% 尾部不改变发展指标与选参。
- `cargo fmt --check`、Clippy、Swift 6 生产源码类型检查、脚本语法检查及 `git diff --check` 通过。
- 显式 Rust/Swift 函数均不超过 50 行（包含签名、注释与空行）；新增函数都有中文输入/返回说明。
- V0.4.0 Apple Silicon 本地应用、ZIP 与 SHA-256 已构建，plist 和 ad-hoc 签名校验通过；资源随包包含本版文档和等差配置示例。
